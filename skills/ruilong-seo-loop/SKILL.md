# 瑞龙旅行 SEO 每日循环

**read → judge → fix → write → measure → repeat**

这个技能的核心观点：**SEO 难在判断，不难在写作。** 写一篇文章很便宜；贵的是判断——哪个词值得做一页、哪一页该修、哪个词是陷阱。所以这个技能的产出永远是**一份很短的待办**，不是一堆关键词清单。

还有一件大多数 SEO 做法会漏掉的事：Search Console 只告诉你谁**点进来**了，不告诉你谁**留下来询价**。一篇 400 点击、0 询价的文章是漏水，不是成绩；一篇 40 点击、6 询价的冷门攻略才是该复制的方向。**我们按询价写，不按排名写。**

瑞龙旅行的客户主要是在意大利（及欧洲）的华人，网站内容中英文都有，产品是跟团游、一日游、邮轮、签证服务、定制行程。「转化」= 询价：表单提交、WhatsApp、电话、微信。

## 先判断用户要做哪件事

| 用户在说什么 | 走哪条路 |
| --- | --- |
| 上传了 GSC / GA4 表格，或说「跑一下 SEO」「这周 SEO 怎么样」 | **A. 跑循环出待办** |
| 问某一个词 / 某一页：「这个词值不值得写」「这页为什么没人点」「这篇该怎么改」 | **B. 单点判断**（读 `references/playbook.md` 对应小节） |
| 「怎么装追踪」「怎么接 Search Console」「怎么上 Bing」「重定向对不对」 | **C. 搭建**（读 `references/setup.md`） |

## A. 跑循环出待办

### 1. 拿数据

脚本在本技能的 `scripts/` 目录，零依赖，需要 Node 18+。数据放在一个可写目录（下称 `DATA`），按优先级：

1. **用户上传了文件**：放进 `DATA`，改名为下表的文件名。中文界面导出的列名（热门查询、点击次数、展示、点击率、排名、着陆页、会话、关键事件）脚本能自动识别。xlsx 先转成 CSV（UTF-8）。
2. **有服务账号密钥**（环境变量 `GSC_SERVICE_ACCOUNT` 或用户给了 JSON 路径）：加 `--api`，脚本自动拉最近 7 天和前 7 天。
3. **什么都没有**：先用 `--sample` 给用户看看报告长什么样，再告诉他们需要导出哪些文件（见 `references/setup.md`「数据怎么导出」）。不要编造数据。

| 文件 | 内容 | 缺了会怎样 |
| --- | --- | --- |
| `gsc_current.csv` | 最近 7 天 **query × page** | 必需 |
| `gsc_previous.csv` | 再往前 7 天 | 没有 decaying 标记 |
| `conversions.csv` | GA4 按落地页的会话数和询价数 | 没有「点击 × 询价」判断——**这是最重要的一张表，缺了要明确提醒用户** |
| `targets.csv` | 每页主攻的词（`page,target_query`） | untargeted 退化为按 URL 猜，误报会变多 |

注意：Search Console 网页界面的「查询」和「网页」是分开导出的，没有 query × page 对应关系。如果用户只给了分开的两张表，照样分析能分析的部分（no_clicks、ai_mode 可以按词做），并说明缺了什么。

### 2. 跑脚本

```bash
node <技能目录>/scripts/seo-loop.mjs --dir DATA            # CSV
node <技能目录>/scripts/seo-loop.mjs --api --dir DATA      # API
node <技能目录>/scripts/seo-loop.mjs --sample --out DATA   # 示例
```

可选 `--config <路径>`：阈值、品牌词、意图规则都在 `scripts/config.json`，要调整就复制一份改后传进去。

脚本输出 `DATA/report.md`（人读）和 `DATA/report.json`（结构化）。**脚本只负责打标记，标记是候选，不是结论。** 接下来的判断才是这个技能的价值。

### 3. 判断（这一步是你的工作）

读 `report.json`，按下面的顺序过一遍。判断细则在 `references/playbook.md`，遇到拿不准的标记就去读对应小节。

1. **先看「点击 × 询价」表。** 找出漏水页（点击高、询价 0）和金矿页（询价率高）。后面所有决定都要参考它：金矿页相关的词优先做，漏水页相关的词先别加码（漏水页上的 almost_there 也跳过）。
   - 表里「—」「无转化数据」表示 GA4 里没有这一页，**不等于没有询价**，别当成漏水。
   - 如果 conversions.csv 的会话数明显多于 GSC 点击（例如 410 会话、121 点击），说明导出时没有只筛自然搜索，询价率会失真，要在「数据缺口」里提醒用户。
2. **修优先于写。** 同一页同时有 no_clicks 和 wrong_intent，说明问题出在页面形态，改标题救不了。
3. **almost_there 是免费流量**，排名 3–10 的优先于 11–20，展示多的优先。
4. **untargeted 的词不能直接写。** 先分两种情况：
   - 这个词其实是所在页面主题的**另一种说法**（换了语言、加了出发地、换了个同义词，例如红叶团页上的「japan autumn tour from milan」）：当成 almost_there 处理，在原页加一句，不用新建页面。
   - 真的是新主题：先看 SERP（有 WebSearch 就搜，看前 5 名是谁）。排在前面的如果是意大利本地人、背包客、纯信息网站，就不是我们的客户，划掉。
   - WebSearch 的结果通常不是意大利本地的搜索结果，而我们的客户在 google.it 上搜。用它做初筛可以，但要在待办里请用户用无痕窗口在 google.it 上复核关键词。没有搜索工具时，把词列为「待核实」，并写清楚要看什么。
5. **不要让搜索量决定页面存不存在。** 搜索量只用来排序。
6. **品牌词（瑞龙 / ruilong）、首页、明显的噪音词直接忽略。**
7. **每个标记最多挑 1–3 条，整份待办一般不超过 8 条。** 宁可少而准。一个标记下没有值得做的，就不写。
8. **脚本的判断可以推翻。** 意图分类和 untargeted 是按规则猜的，内链只给候选（从中挑主题真正相关的一对，不相关的不要硬链）。推翻脚本判断时，写一句为什么。

### 4. 输出格式

按这个模板写，用中文，短句，每条都要能直接动手：

```markdown
# SEO 待办 · <日期>

**本周一句话：** <最重要的发现，例如「冰岛极光那篇 121 点击 0 询价，别再加码；多洛米蒂一日游 4 点击 4 询价，照它再写 3 篇」>

## 点击 × 询价
| 页面 | 点击 | 询价 | 判断 |
（只列有判断的页面，最多 5 行）

## 今天就做（每条 ≤ 30 分钟）
1. **[almost_there]** 在 `/tours/japan-autumn/` 第二段加一句：「……（含原词「日本红叶跟团游」的完整句子）」——排名 6.1，610 展示
2. **[no_clicks]** `/blog/japan-visa-guide/` 标题改为：「……」，meta 改为：「……」——1850 展示只有 1 点击
…

## 本周做
- **[wrong_intent]** …（需要改页面形态的，写清楚改成什么：对比表 / 价格表 / 报名按钮）
- **[新页面]** 标题：「……」，目标词：「……」，为什么：<关联金矿页 / 长问句原话>，先核实：<SERP 要看什么>

## 划掉的词
- 「……」——原因（SERP 是本地人 / 意图不对 / 和金矿页无关）

## 内链
本月：`/A/` → `/B/`，锚文本「……」

## 数据缺口
（缺 conversions.csv / targets.csv / 上周数据、会话不是只含自然搜索、询价数据不足 2–4 周、SERP 需要在 google.it 复核等，写在这里，并说明缺了会少看到什么）
```

具体句子要真的写出来（标题、meta、要插入的那句话），不要只写「优化标题」。给出的标题和句子要包含原查询词，用搜索者的原话，中文词配中文句子，英文词配英文句子。

### 5. 边界

- 只给待办，**不自己发布或修改网站**。用户明确让你改（比如通过 WordPress 工具）时才动手，而且一次只改一页，改之前把改动给用户看。这是循环里「是否上线由人决定」的那一环。
- 数据很少（总展示 < 1000）时，别过度解读：说明样本太小，重点放在技术问题（收录、重定向）和追踪搭建上。

## B. 单点判断

用户问的是某个词或某一页时，不用跑脚本。读 `references/playbook.md`，按对应小节回答：

- 「这个词值不值得写」→ 「毙掉坏关键词」
- 「这页有展示没点击」→ 「先修再写」+「页面类型」
- 「这页流量掉了」→ 「decaying 排查」
- 「写什么新页面」→ 先问有没有询价数据；有就从金矿页的题材出发，没有就先帮他装追踪
- 「怎么让 ChatGPT / AI 搜到我们」→ 「写在 AI 在看的地方」

## C. 搭建

读 `references/setup.md`。常见的是：装落地页追踪（`scripts/landing-tracker.js`）、接 Search Console API、查重定向、上 Bing + IndexNow、设置每天自动跑。
